# Contrato de trabajo por caso

Consultar primero la ficha con `python scripts/informe.py protocolo CODIGO`. Sus IDs son exactos, en minúsculas. Los nombres visibles del informe vienen de la ficha institucional. `protocolo` sin código lista las fichas.

## Fuente de un paciente

Objeto `fuente.json` con `caso` (identificador local sin espacios), `protocolo`, `paciente`, `tecnica`, `hallazgos` y `medidas`. `paciente` requiere `nombre` y `modalidad` y permite `edad` (entero o texto como «5 meses»), `sexo`, `medico`, `procedencia`, `fecha` (DD/MM/AAAA) y `hora` (hh:mm AM/PM). Fecha y hora omitidas se completan como fecha/hora de emisión en Managua. Indicar las del estudio si se conocen y corresponde al informe. La fuente acepta `indicacion`, una `clasificacion` o una lista `clasificaciones`, y el booleano opcional `recomendaciones_solicitadas`. El valor explícito `false` excluye recomendaciones para ese caso.

`hallazgos` usa un objeto por ID de estructura del protocolo. Para `evaluado`, consignar `{"estado":"evaluado","campos":{"id_del_campo":"observación comprobada"}}` con todos los campos de la ficha. Si el radiólogo documentó evaluación parcial, usar `parcial` con `motivo` y los campos realmente observados. Usar `no_evaluable` con `motivo` para un impedimento real, o `fuera_de_alcance` con `motivo` si esa estructura quedó expresamente fuera del examen. Las dos últimas opciones llevan el motivo en la fuente y carecen de `campos`. Un dato ausente requiere consulta y queda sin autorizar para generación.

`medidas` es una lista de objetos. Cada uno tiene `estructura`, `id`, `parametro`, `valores` (1 a 3 números), `unidad` e `interpretacion`. Emplear el ID de ficha para medidas esenciales, como `longitud` renal o `pre` y `pos` en residuo. Para una medida adicional crear un ID único dentro de su estructura. Documentar tres ejes solo si corresponden a la misma estructura, lesión o colección en planos ortogonales. Para residuo escalar usar mL o cm³, o introducir tres ejes en mm/cm por medición. `clasificacion` lleva `sistema`, `categoria` y `sustento`, por ejemplo `BI-RADS`, `BI-RADS 2` y su fundamento concreto. Registrar `version` cuando se conozca y `estructura` y `objetivo` para identificar la lesión o el ámbito que recibe la categoría. Con `clasificaciones` los tres campos adicionales son obligatorios por entrada. La versión debe corresponder al documento aplicable a la modalidad.

## Redacción y salida

`python scripts/informe.py abrir fuente.json casos` devuelve `directorio`, `caso`, `token` y huellas. Preparar un `redaccion.json` nuevo con `caso`, `token`, `fuente_sha256`, `tecnica`, `hallazgos` y `conclusiones`. Cada hallazgo lleva `campos` con los mismos IDs y texto reformulado, más `destacar` opcional. Para `parcial` incluir el campo `motivo` junto a los evaluados. Para `no_evaluable` incluir solo `motivo`. Para `fuera_de_alcance` usar `"campos":{}`. Cada conclusión tiene `diagnostico`, `sustento` y `estructuras` (lista de IDs evaluados). `etiologia` es un objeto opcional y `diferenciales` una lista opcional de objetos. Cada uno lleva `hipotesis`, `sustento` y `estructuras` evaluadas. Separar la causa probable de las alternativas plausibles y ordenar estas últimas por pertinencia. `recomendaciones` es una lista de textos clínicos concretos cuando procedan. `atlas` permite seleccionar una lámina de litiasis renal por `lado` (derecho o izquierdo), `segmento` (inferior, medio, superior, pelvis o union_pieloureteral) y `estructura` (ID renal evaluado). Usarla solo para litiasis sustentada del problema principal en la localización indicada. Identidad, medidas y clasificación se transfieren desde la fuente y se omiten del JSON de redacción.

`python scripts/informe.py revisar DIRECTORIO redaccion.json` permite ejecutar las validaciones de fuente, redacción y cálculos sin renderizar. Generar vuelve a ejecutarlas.

`python scripts/informe.py generar DIRECTORIO redaccion.json` crea una revisión con Word, PDF, PNG por página y verificaciones. Inspeccionar todos los PNG y la fuente. Solo entonces ejecutar `python scripts/informe.py entregar DIRECTORIO REVISION --paginas 1 2 --cotejado`, usando la lista real de páginas. La orden deja registro de una revisión técnica declarada, no de una firma clínica. Ver los ejemplos completos en el paquete de pruebas. El Word es la entrega principal. El PDF sirve para revisión y puede entregarse cuando se solicite.
